Group project research and proposals Assignment/Milestone
Your newly formed group will be pitching  and writing up proposals for THREE possible projects, which myself and some other faculty/industry folks will give recommendations on the most viable and feasible project. The project will be your central focus for the last third of the semester, and most of my lectures and demo sessions during those weeks will be aligned with skills and code you willneed to complete the major group projects.
There is substantive work your group needs to put in for each idea (for this proposal assignment and pitches), including research, creating initial data models, mocking up possible data visualizations, and the like.
You are pitching three different project ideas, based on creating a website that would explore a topic and its underlying data and provide interactive data visualizations that prove a conclusion that users can interactive with to simulate possible future outcomes.
For each idea your team needs to put together the following for ALL THREE ideas:

Project focus: Description of the data area, problem or question you would address and answer. This must include tangible areas for conclusions or insights (what would you hope to discover / prove).
Data research: Perform some research then explain and cite sources from which you could collect (additional) raw data and information. While these will likely be web-based (direct page stats or downloadable), they could be government statistics (LOTS of data sets available many of them quite large), media articles, publically available university research, (free) trade group data, publically available user studies, etc.
Data model: You will be creating a database to store the data, write queries on it, etc. In your proposal for each topic you need to build and include a data model (screenshot, pdf) that you can build in Verterbo or by hand. You are NOT building the database at this point (when you do one member of your team will get assitance from the instructure and course assistants). Data models must include multiple tables/entities, with a draft of fields listed, and with relationships between tables/entities.
Sample data viz: Some examples of kinds of data visualizations that would make sense for that data, as well as explanations of what data you would be flowing in. For instance traditional charts, heatmaps, geographic maps, word clouds, venn diagrams, etc. For these samples you must mock up how the real data might be represented. This can consist of modifying existing illustrations to edit label and key values (to terms from your area), but do you do not need to edit the actual core content (pie chart sizes and colors, geomap region and plots, bar length and sizes, etc.). So you do not need to create these (can paste in samples), but SHOULD mock them up/edit them to represent meaningful (topic-specific) data.
Team roles: A first pass on which roles each team member thinks they might serve. If this would be the same for all three potential projects you can just note that and list it once. These can include the following, but you are welcome to add other roles too, and note some team members may serve in multiple roles (while others might have a singular focus all project):

Project manager
Head of research and q/a (including user testing)
Graphic designer (and production)
Web designer (html, css)
Front-end dev (Javascript, jQuery, json)
Database administrator (create db, SQL queries for pages)
Back-end dev (php, create web APIs with some instructor and assistant help)
