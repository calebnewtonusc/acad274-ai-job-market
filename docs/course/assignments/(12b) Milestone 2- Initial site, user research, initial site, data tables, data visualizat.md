Project Milestone 2: Initial site, user research, initial site, data tables, data visualization variations
In this build you will forward many of the aspects of the project and M1, including building out the web site, and do some user (consumer) research.

User research: Talk to consumers / the potential audience for your work. Yes, this can include peer students, but for many of your projects it should also at least one industry person... although you are allowed to use faculty for that (i.e. Thomas for social, MikeK or Matthew for many of the subjects). Industrious groups could reach out to real/actual involved personages, such as city employees, although with the small turnaround you should try to contact asap... but you would be surprised how many city and other officials will respond to politely worded student requests : )Deliverable: Document/s with notes on user interviews (actual comments), including what conclusions or actions they would be interested in from your data area (convincing proof of relationship between x and y, recommendations for how they should act/device on related, etc.). Note: You need to document/list the identities AND roles for reach interviewee (Patrick, a student interested in sports statistic analysis) . 
json outputs of data: One member of your team should create one or more php pages that output database data (generally statistics) as a json object, so others can "call" the page from their files to be able to create data grids/tables and data visualizations from the data. Note: We will have a workshop/demo in class that will show you how to do this including step-by-step instructions and examples. Deliverables:  One or more php pages that output database query output as a json object. See "Convert php db query to json" Lecture entry for a walkthrough and overview. 
Rendered data visualizations (and data tables): Charts, graphics, maps, etc., whose data is rendered from your initial database outputs. Note: For this build they do NOT have to be live rendered, such as from javascript charting libraries, but could be illustrations you rendered by pasting data output into charting apps (i.e. you could copy data from DataGrup or from a webpage table output of your data, paste it into Google Sheets, and create charts from there and save screenshots). But they DO have to be based on actual data output from your database (which will also be present in web-based data tables). Deliverables: In webpages, THREE DIFFERENT data output tables (data grids) accompanied by three different data visualizations each. So that is nine visualizations total (3x3). Since each member of your team is required (for their individual lab) to create multiple visualizations, this task should just be about picking the best and putting together webpage/s to house them. You can create one page per data table (+3 visualizations) or put all of them on one page. Note: For Milestone2 these can be live rendered (from a json feed or php script) or you could render the tables and paste the html code into the page. Later builds will require live data and chart renderings. We will have in-class workshops/demos on generating live data tables and charts from json feeds. 
Interactive visualization ideas (for M3 and M4): Initial ideas of how you could make visualizations of your data interactive, from charts with sliders to other custom components. You are not committing to an implementation (yet), but brainstorming/documenting some ideas. Deliverables: Could be a stand-alone doc or could add paragraphs of text accompanying the data viz deliverables (above). If the latter have the clearly labelled (like "Interactive ideas").  
Initial website that contains pages on below. Site pages must use a shared extenral stylesheet. Most of these are STATIC pages (except the required data page/s).

Homepage that includes purpose and assumptions of your project.
Resources Page with links and summaries of seminal resources in your area. This can include statistical sites (commercial or non), academic papers, research and/or jouralism studies, etc. Each item should have at least a one sentence summary.
Data page/s: Depending on how many conclusions and how in-depth, one or more pages that contain BOTH data tables/output and feature your rendered data visualization ideas (from above). Note: If you work this correctly it is the same deliverable from the data viz requirement of M2.
(Optional) You could choose to create a page publishing all of your user research (from M2 requirements), rather than just pasting it all into a google doc. But NOT required to have it as a page of the site.


Upcoming milestones will have you refine and develop live data visualizations (if the ones in your M2 were static), interactive visualizations and other components, and further build out your datasets/databases.
